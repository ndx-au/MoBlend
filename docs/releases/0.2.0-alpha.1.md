# MoBlend v0.2.0-alpha.1

First alpha for controlled evaluation on **Linux amd64**. Interfaces and behavior
may change as qualification continues. This is a prerelease, not a stable release.
The repository's existing access permissions apply to these downloads.

## What is included

- Native Go `blendctl` executable with embedded scene/project/module schemas,
  catalogue, fonts, trusted Blender Python and first-party asset pack.
- Strict JSON validation and deterministic compilation; text, forms, materials,
  camera/lights, bounded animation and the column-chart Geometry Nodes asset.
- Local module composition, explicit aliases/namespaces and source-aware
  diagnostics; independent shot selection and snapshot dependency provenance.
- Isolated preview/render jobs, editable `.blend` output, PNG frame sequences,
  complete/failed manifests, process-tree cancellation and bounded subprocess logs.
- Fixes for module alias ambiguity and camera targets, interpolation ownership
  for transform/material tracks, original source pointers, path/input limits,
  malformed outputs and concurrent successful/failed-shot attribution.
- Versioned native package with guide, examples, tiny smoke scenes, user docs,
  build/runtime provenance and font license/notice. No Node/npm dependency.

CLI version: **0.2.0-alpha.1**. Scene/project/module contracts: **1.0.0**.
Asset pack: **0.1.0**. These version contracts remain separate.

## Requirements and installation

Only **Linux amd64** is qualified for this alpha. Install Blender separately.
The exact tested runtime is **Blender 5.3.0 Beta**, build **7e7c173d45c8**, with
CPU Cycles. The CLI currently gates the 5.3 family, but other builds are not
established by this evidence. A stable Blender baseline remains a follow-up.

Download `blendctl_0.2.0-alpha.1_linux_amd64.tar.gz` and `SHA256SUMS` from this
release, then run in that download directory:

```bash
# Check the archive before extraction; the unpacked binary is not present yet.
sha256sum --ignore-missing -c SHA256SUMS
tar -xzf blendctl_0.2.0-alpha.1_linux_amd64.tar.gz
# Now verify both the archive and executable.
sha256sum -c SHA256SUMS
cd blendctl_0.2.0-alpha.1_linux_amd64
./blendctl version
./blendctl doctor
./blendctl validate examples/title.json
./blendctl preview testdata/compile/title_small.json --frame 24 --out /tmp/moblend-alpha-preview
```

Set `MOBLEND_BLENDER=/absolute/path/to/blender` if the tested Blender executable
is not on PATH. Put `blendctl` on PATH or invoke it directly from the package.
No Go, Node/npm, separate Python installation, hosted model or network connection
is required for ordinary local use. Blender supplies its own Python runtime.

Only a job manifest marked `complete` establishes render success; inspect the
returned job path rather than assuming a PNG or `.blend` alone is complete.

## Verification scope

Release qualification includes Go formatting/vet, the full Go test suite with
real Blender integrations, and native packaging acceptance covering repeated
archive bytes, checksums, extraction and tag/dirty/version/output guards.
The exact tagged package is rendered and its saved scene reopened before upload;
draft assets are downloaded and compared to the verified package before publication.
BUILD-INFO records commit, version, clean release mode, toolchain/runtime and render check.

## Known limitations

- Alpha contracts may evolve. No cross-GPU/OS/Blender pixel-identity promise.
- macOS, Windows, additional Blender builds and GPU profiles are not qualified.
- Actual-model authoring/repair-loop and unsupported-prompt refusal evaluation
  remain incomplete; prepared fixture renders are not model-performance evidence.
- Existing smoke visual evidence is limited; full HD aesthetic approval is not claimed.
- No RAG, hosted model service, arbitrary Python/user `.blend` loading, external
  asset downloads, MP4/audio pipeline, parameterized modules or build cache.
- Input snapshots are per file, not atomic filesystem transactions; execution
  hygiene is not a hostile-code/filesystem sandbox. Job retention is manual.

The project currently declares no software license. This release does not add
one; third-party DejaVu Sans license and notice are bundled unchanged.

The old local `0.1.0-rc1` label records an earlier packaging milestone and is
preserved as history; it did not establish stable product qualification.
